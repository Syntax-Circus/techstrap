# Webhook Notifications Implementation Plan

Approved design: the global and product webhook plan in this conversation.

**Goal:** Deliver summary notifications to Discord and generic JSON endpoints with inherited product configuration.

**Architecture:** Separate persisted webhook settings and delivery records. Capture ticket events and feature changes before unit-of-work commit; lease and send deliveries in the worker. Admin uses API handlers and Contracts only.

**Constraints:** .NET 10; no new package dependencies; EF-generated migration; admin-only configuration and operations; no requester data or access tokens in payloads; destinations are secret and masked on reads.

## Tasks
- [x] Configuration: Contracts, policy tests, store abstraction, EF settings model and concurrency, active-agent handler and admin API.
- [x] Capture: transactional precommit staging; ticket creation/status events and feature creation/progress; defaults, filters, rollback and replay tests.
- [x] Delivery: outbox model, concurrent leases, immutable snapshots, SSRF-safe HTTP transport, Discord renderer, retries, cancellation, history/test/retry/discard, retention.
- [x] Admin: global settings page, product override section, endpoint forms and status selections, test and delivery actions.
- [x] Verification: generated migration, targeted tests, architecture/build/configuration checks, documentation and final review.

## Review focus
Rollback and replay cannot queue duplicates. Implicit status transitions must notify. Masked secrets must survive unchanged saves. DNS rebinding and redirects cannot bypass destination validation. Worker failures cannot expose URL tokens in telemetry.
