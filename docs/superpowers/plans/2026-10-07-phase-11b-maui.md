# PHASE-11b MAUI helper: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `TechStrap.Client.Maui` (P11-T07, T08, T09): a `net10.0` NuGet package that collects device and app metadata through the MAUI Essentials abstractions and submits a ticket through `TechStrap.Client`, in one pull request, with the shared metadata key names in Contracts.

**Architecture:** One plain `net10.0` class library (no `UseMaui`, no platform target frameworks) depending on `TechStrap.Client` and `Microsoft.Maui.Essentials`; every platform value is read through an injected interface (`IAppInfo`, `IDeviceInfo`, `IConnectivity`, `IDeviceDisplay`, `IBattery`), so the collector is unit-tested with NSubstitute and the real implementations (`AppInfo.Current` and friends) are registered lazily as defaults for the app. `IDeviceContextCollector` builds the metadata dictionary; `IMauiTicketSubmitter` merges it with the app's own metadata (collected keys are reserved), pre-checks the server's limits locally and calls `ITechStrapClient`. Collection never throws into the app: a platform accessor that fails skips its field.

**Tech Stack:** .NET 10 (SDK 10.0.401), `Microsoft.Maui.Essentials` 10.0.110 (replaces the unused `Microsoft.Maui.Controls` pin), `Microsoft.Extensions.DependencyInjection.Abstractions` + `Microsoft.Extensions.Options` 10.0.12, `SyntaxCircus.Common` `Result<T>` (via Client), xUnit v3 + Shouldly + NSubstitute, Pester.

**Spec:** `docs/architecture/PHASE-11-client-sdk.md` (Architecture Decisions "MAUI metadata capture", "MAUI submit helper", "Public-key guidance"; tasks P11-T07 to T09; Corrections (D-047)); `docs/architecture/04-DECISION-LOG.md` D-001 (Public keys: metadata stored but flagged untrusted), D-005, D-047; the owner decisions of 2026-10-07 below, recorded as **D-048** in Task 5.

### Owner decisions (2026-10-07), recorded as D-048
1. **Single `net10.0` target framework.** The spec's `net10.0-android;net10.0-ios;net10.0` and D-047's CI split (Android on ubuntu, iOS on a macOS tag job) are withdrawn: all of 11b's code is interface-only Essentials usage, which a workload-free SDK restores, builds and tests (spike, 2026-10-07: `mcr.microsoft.com/dotnet/sdk:10.0`, 3/3 tests, 0 warnings). `net10.0` is consumable by every `net10.0-*` MAUI app; `DeviceInfo.Current` etc. resolve to the platform build at runtime. Platform TFMs can be added later without breaking consumers. `UseMaui` is never set (it demands a workload: NETSDK1147).
2. **One pull request** for T07 to T09 plus the close-out.
3. **The design presented and approved on 2026-10-07** (below): `TicketMetadataKeys` in Contracts, `MauiTicketDraft` parameter object, reserved keys, local limit checks, lazy Essentials defaults.

### Decisions made while drafting (D-048 records them)
- **`Microsoft.Maui.Essentials`, not `Microsoft.Maui.Controls`.** The spike packed both: Essentials gives 3 transitive packages, Controls about 19. The `Microsoft.Maui.Controls` 10.0.110 pin (used by nothing) is replaced by `Microsoft.Maui.Essentials` 10.0.110 in `Directory.Packages.props` and `03-PACKAGE-MAP.md`. Consumers need MAUI 10.0.110 or newer (known limit).
- **Key names live in Contracts** (`TechStrap.Contracts.Intake.TicketMetadataKeys`): they cross the wire and the Admin may render known keys. SDK-only types stay in `TechStrap.Client.Maui`.
- **`IntakeLimits.MaxMetadataJsonLength = 16_000`** mirrors `DomainLimits.MetadataMaxLength` (`src/TechStrap.Domain/Rules/DomainLimits.cs:35`), kept equal by `IntakeLimitsParityTests` like the other copies, so the submitter can refuse an oversized dictionary locally.
- **Submitter signature:** `SubmitAsync(MauiTicketDraft draft, CancellationToken ct = default)` with `MauiTicketDraft(string Subject, string Message, string RequesterEmail, string? RequesterName = null, IReadOnlyDictionary<string, string>? Metadata = null, string? IdempotencyKey = null)` instead of the spec's positional parameters: 11d adds attachments as one more property without breaking callers.
- **Merge rule:** collected keys are reserved; an app value for a reserved key is ignored (the spec: "app-supplied values winning only for non-reserved keys"). More than `IntakeLimits.MaxMetadataKeys` entries or more than `MaxMetadataJsonLength` serialized characters is a local `Result` failure (`metadata-invalid`, `ResultErrorKind.Validation`, target `metadata`, the server's own code) and nothing is sent.
- **Collection never throws.** `MauiDeviceContextCollector` wraps each accessor read; `NotImplementedInReferenceAssemblyException` (plain net10.0 at test time), `PermissionException`, `FeatureNotSupportedException` or any other exception skips that field. No logging (the package has no logger, like `TechStrap.Client`).
- **Lazy defaults.** `AddTechStrapMaui` registers `IAppInfo => AppInfo.Current`, `IDeviceInfo => DeviceInfo.Current`, `IConnectivity => Connectivity.Current`, `IDeviceDisplay => DeviceDisplay.Current`, `IBattery => Battery.Default` with `TryAddSingleton` **factories** (the static accessor is read on first resolve, never at registration), so an app or a test that registered a substitute first wins and the plain-net10.0 DI test does not touch the platform statics.
- **Two registration overloads:** `AddTechStrapMaui(this IServiceCollection, Action<DeviceContextOptions>? configure = null)` requires the app to have called `AddTechStrapClient`; `AddTechStrapMaui(this IServiceCollection, Action<TechStrapClientOptions> configureClient, Action<DeviceContextOptions>? configure = null)` calls both.
- **Extras are opt-in flags** (`IncludeDisplay`, `IncludeBattery`), not a free-form list; `Redact` is `Func<string, string, string?>` (key, value -> replacement, or null to drop the field) applied after truncation to every collected field.
- **The pack dry run and `Test-PackageContents.ps1` gain the third package** with the expected set `TechStrap.Client`, `TechStrap.Contracts`, `Microsoft.Maui.Essentials`, `Microsoft.Extensions.DependencyInjection.Abstractions`, `Microsoft.Extensions.Options`. *(As built: five dependencies, not four; the direct `TechStrap.Contracts` project reference adds the fifth.)*
- **Carried from 11a:** no `GitVersion.MsBuild`, `GenerateDocumentationFile` or SourceLink package (11c); README minimal and ASCII; `IsPackable` comes from `eng/Packaging.props`.

## Review Focus
1. A platform accessor that throws (`DeviceInfo.Current` on a desktop target, a denied permission) must skip its field, not fail the submit - Task 3 `A_throwing_accessor_skips_its_field_and_the_rest_is_collected`.
2. An app metadata value that is null, blank or longer than 1000 characters: a reasonable app expects blanks dropped and long values truncated rather than a server 400 - Task 4 `App_metadata_is_truncated_and_blank_values_are_dropped`.
3. An app key that collides with a collected key must not spoof device data - Task 4 `An_app_value_for_a_reserved_key_is_ignored`.
4. Disabling device context must leave only the app's own keys (nothing `app.*`, `os.*`, `device.*`, `locale`, `timezone`, `network.*`) - Task 4 `Disabled_device_context_sends_only_app_metadata`.
5. Registering `AddTechStrapMaui` twice, or after the app registered its own `IDeviceInfo`, must neither duplicate services nor replace the app's - Task 4 `AddTechStrapMaui_is_idempotent` and `An_app_registered_IDeviceInfo_wins`.
